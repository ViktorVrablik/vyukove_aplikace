Git a GitHub

Interaktivní simulátor verzování — piš příkazy a sleduj, co dělají s historií

Zpět
Původní zdroj: simulátor vychází z myšlenky a struktury úrovní projektu Learn Git Branching, jehož autorem je Peter Cottle (open source, licence MIT). Tato česká verze je napsaná znovu a přizpůsobená pro výuku; původní aplikaci doporučujeme jako rozšiřující materiál.
Základ
Git a GitHub

Git je systém pro správu verzí. Ukládá historii projektu jako řadu snímků, takže se lze kdykoli vrátit, porovnat změny nebo pracovat na více věcech současně.

GitHub je služba, která hostuje git repozitáře na internetu a přidává nástroje pro spolupráci — pull requesty, kontrolu kódu (review), úkoly (issues) a automatické testy.

Základ
Commit

Commit je uložený snímek všech souborů projektu. Každý má jedinečný identifikátor (hash, např. 3f9a2c1), zprávu, autora a odkaz na rodiče.

V simulátoru se commity jmenují zkráceně C0, C1… a kopie vzniklé rebasem nebo cherry-pickem dostávají apostrof: C2'.

Větvení
Větve a HEAD

Větev je pohyblivý ukazatel na commit. Při novém commitu se posune dopředu.

HEAD říká, kde právě jsi. Obvykle ukazuje na větev; když ukazuje rovnou na commit, mluvíme o odpojené HEAD.

Větvení
Merge vs. rebase

Merge spojí dvě větve slučovacím commitem se dvěma rodiči. Historie zůstává přesně taková, jak vznikla.

Rebase zkopíruje tvoje commity na konec jiné větve. Historie je rovná a přehledná, ale commity se přepisují — nepoužívej ho na práci, kterou už mají ostatní.

Soubory
Tři oblasti gitu

Pracovní adresář (soubory, které upravuješ) → git add → přípravná oblast (staging) → git commit → repozitář.

Simulátor se soustředí na historii, takže soubory neřeší — git commit v něm rovnou vytvoří commit.

GitHub
Lokální a vzdálený repozitář

Na svém počítači máš celou kopii projektu. Vzdálený repozitář (origin) je společná kopie na GitHubu.

Větev origin/main je tvoje poslední známá podoba větve main na GitHubu. Aktualizuje se jen při fetch, pull a push.

GitHub
Pracovní postup v týmu (GitHub flow)
git switch -c feature git commit git push -u origin feature pull request + review merge na GitHubu git pull

Do main se nepíše přímo. Každá úloha má vlastní větev, která se přes pull request zkontroluje a teprve potom začlení. Když ti GitHub odmítne push, znamená to, že někdo odeslal práci před tebou — nejdřív git pull, pak znovu git push.
